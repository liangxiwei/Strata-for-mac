# Mac 上的 IQ2_XS 和 Q2_0，2026-10-04

> 仓库里保留本目录的 README、汇总和驱动脚本。`iq2_xs.json`、`q2_0.json` 是自动模式的结果；`*.high-power.json`
> 是高电量模式（`iq2_xs.high-power-2.json` 是高电量下的第二次），`*.low-power.json` 是低电量模式。原始运行输出
> （`run/`）只留在测量的机器上，不进 git。

Apple M2 Max（38 核 GPU、96 GB），macOS 26.5，Xcode 26.1。

- **接电源，能耗模式为"自动"**（`pmset -g` 的 `powermode 0`）。同一台 Mac 也在低电量（`powermode 1`）和高电量
  （`powermode 2`）模式下测了，结果放在下面对比。
- 两个模型都由 `./setup.sh --setup --model <size>` 装好，配置是 setup 写出的，图片开启。
- 引擎二进制相同，SHA-256 为 `71cb4981…`。
- `run.py` 和 `../2026-10-03-metal-readme/run.py` 是同一个脚本，只多了 `--config` 参数。测的是：
  - 4 段新的短对话，每段生成 256 token；
  - 一个 30,000-token 的文档，读入新上下文。
- 条件：一个引擎，没有其他引擎在跑，temperature 0，关闭思考，不复用前缀。

## Q2_0 的下载

- shard 1 共 37.6 GB，经 hf-mirror 用 4 条连接并行下载。单连接实测约 3.3 MB/s，4 条连接在 6.7-15.7 MB/s 之间波动，
  用时约 45 分钟。
- 下完后 SHA-256 为 `69820c02…`，与 Hugging Face 公布的一致。
- shard 2 与 IQ2_XS 的 shard 2 是同一个文件，SHA-256 都是 `316b46f3…`，所以直接硬链接，没有下载。
- `tools/iq_pack.py` 生成原生 pack 用时约 3 秒，setup 总共用了 3 s。

## 结果（自动模式）

| 运行 | IQ2_XS | Q2_0 |
| --- | ---: | ---: |
| 短对话 1-4 写回答 | 29.24 / 28.77 / 28.38 / 28.43 token/s | 26.76 / 26.69 / 26.67 / 26.67 token/s |
| 30,000-token 文档读取 | 108.4 s，**276.8 token/s** | 108.5 s，**276.5 token/s** |
| 读完后写回答 | 27.4 token/s | 25.6 token/s |
| 专家缓存（全部常驻） | 24,576 个，33.02 GiB | 24,576 个，31.64 GiB |
| 全部载入后剩余的 GPU 内存 | 39,453 MiB | 41,011 MiB |
| 启动 | 98.7 s | 105.7 s |

和 IQ2_XS 比，Q2_0 写回答慢约 7%，读提示一样快，专家少占 1.4 GiB。两个模型的引擎日志都显示 token graph 在 GPU
上决定专家，没有 CPU 专家。

首页写的是短对话的中位数取整：IQ2_XS 29 / 277，Q2_0 27 / 276 token/s。

## 三种能耗模式对比

同一台 Mac、同一个引擎二进制、同一份配置和输入，只有能耗模式不同。

| | 低电量 | 自动 | 高电量 |
| --- | ---: | ---: | ---: |
| IQ2_XS 写回答（短对话中位数） | 23.93 token/s | **28.60 token/s** | 27.98 / 28.93 token/s（两次） |
| IQ2_XS 读 30,000 token | 201.8 token/s（148.7 s） | **276.8 token/s**（108.4 s） | 271.7 token/s（110.4 s） |
| Q2_0 写回答（短对话中位数） | 22.68 token/s | **26.68 token/s** | 27.03 token/s |
| Q2_0 读 30,000 token | 205.3 token/s（146.1 s） | **276.5 token/s**（108.5 s） | 275.0 token/s（109.1 s） |

- **低电量 → 自动**：写回答快 17.6-19.5%，读提示快 34.7-37.2%。
- **自动 → 高电量**：没有测出差别。写回答 -2.2% 到 +1.3%，读提示 -1.8% 到 -0.5%，都在同一模式两次运行的波动之内。
  - 高电量下 IQ2_XS 的两次短对话中位数是 27.98 和 28.93，相差 3.4%。
  - 第二次的文档读取只有 253.6 token/s，不算数：那段时间 Chrome 的几个进程合计占了约 300% CPU（每 30 s 的 `ps` 采样）。
  - 高电量模式下测的时候，后台还有 Chrome、WindowServer 和 Spotlight（`mds`）在跑；自动模式那次没有持续采样后台负载。
- 三种模式下，所有运行的回答开头（短对话 24 token、文档 40 token）逐字相同。能耗模式只改变速度。
- 剩余 GPU 内存三次完全一样（39,453 / 41,011 MiB）。
- 启动时间取决于系统缓存里还剩多少专家页，和能耗模式无关：低电量那次 Q2_0 的 shard 1 刚下完，还在缓存里，所以只用了
  29.1 s；高电量那次 IQ2_XS 紧接着自动模式的测试，只用了 36.1 s。

## MTP 草稿在自动和高电量模式下仍然更慢

日用配置不开 MTP 草稿（`--mtp-max-t 1`），这是低电量模式下定的。这次在自动模式下用同一配置、只改 `--mtp-max-t 2`
重测 IQ2_XS（`iq2_xs.mtp-t2.json`）：

| | `--mtp-max-t 1`（日用） | `--mtp-max-t 2` |
| --- | ---: | ---: |
| 短对话写回答 | 29.24 / 28.77 / 28.38 / 28.43 token/s | 20.26 / 21.13 / 20.99 / 20.72 token/s |
| 中位数 | 28.60 token/s | 20.86 token/s（**-27.1%**） |
| 读完 30,000 token 后写回答 | 27.4 token/s | 18.7 token/s |
| 草稿接受 | 无草稿 | 97/127、90/114、102/127、90/118、25/33 |
| 30,000-token 文档读取 | 276.8 token/s | 276.6 token/s |

五组回答开头逐字相同。草稿接受率有 76-80%，但检查草稿的开销比省下的多，所以继续关闭。

高电量模式下再测一次（`iq2_xs.mtp-t2.high-power.json`）：短对话 21.01 / 21.87 / 21.61 / 21.53 token/s，中位数
21.57，比同一模式下关闭草稿的 27.98-28.93 慢 23-25%。草稿接受数和自动模式那次完全相同，回答开头也相同。

这些是速度测量，不是回答质量评测。

## 复现

先确认接了电源，并且能耗模式不是低电量（系统设置 → 电池，或 `pmset -g | grep powermode`：0 自动，1 低电量，
2 高电量）。关掉占 CPU 的应用：高电量第二次那段时间 Chrome 占了约 300% CPU，读提示比第一次慢了 6.7%。

```sh
.venv/bin/python bench/results/2026-10-04-metal-models/run.py --config strata-iq2_xs.json
.venv/bin/python bench/results/2026-10-04-metal-models/run.py --config strata-q2_0.json
```
