# Mac 上的 128K 上下文，2026-10-04

> 仓库里保留本目录的 README、汇总和驱动脚本。`iq2_xs.json`、`q2_0.json` 是自动模式的结果；`*.high-power.json`
> 是高电量模式，`*.low-power.json` 是低电量模式。原始运行输出（`run/`）只留在测量的机器上，不进 git。

Apple M2 Max（38 核 GPU、96 GB），macOS 26.5，引擎二进制与 `../2026-10-04-metal-models/` 相同。**接电源，能耗模式为
"自动"**（`powermode 0`）。同一台 Mac 也在低电量和高电量模式下测了，结果放在下面对比。

## 测法

用 setup 写出的配置，只把 `--max-context` 改为 131072，并去掉图片参数，只测文字路径。其余参数和每天用的一样：FP16
KV，1,024-token 分块，专家全部常驻。

提示按 `../2026-10-03-metal-100k/` 的方法生成：

- 正文是仓库自己的文档和 `src/core/*.cpp`，取自提交 `dc047b5`（`--corpus-rev`），以后改文档不会改变提示。
- 正中间埋一条校验记录：项目代号 银杏，验收日期 10月18日，校验码 AX-7319。
- 结尾要求用一句话答出这三项。
- 套上对话模板后正好 128,000 个 token。提示的 SHA-256（token id 的 JSON）以 `ba9ca84e…` 开头。
  - 高电量那两次的汇总里记有 `prompt_sha256`。
  - 自动模式那两次是在脚本加上这一项之前跑的。按当时的工作区重新生成提示，哈希相同。

每个模型都从新进程开始，不复用前缀，temperature 0，关闭思考。答完后在同一会话里追问一次"校验码是多少"。

## 结果（自动模式）

| | IQ2_XS | Q2_0 |
| --- | ---: | ---: |
| 读入 128,000 token | 631.8 s，**202.6 token/s** | 626.1 s，**204.4 token/s** |
| 首个 token | 631.9 s | 626.2 s |
| 读完后写回答 | 25.3 token/s（27 token） | 24.5 token/s（27 token） |
| 三个字段 | **3/3**：项目代号为“银杏”，验收日期为10月18日，校验码为AX-7319。 | **3/3**：同左，逐字相同 |
| 追问：复用 / 新读 | 128,026 / 24 token，0.88 s | 128,026 / 24 token，0.82 s |
| 追问首个 token | **0.94 s**，回答 AX-7319 | **0.88 s**，回答 AX-7319 |
| 全部载入后剩余的 GPU 内存 | 36,776 MiB（32K 时 39,453） | 38,334 MiB（32K 时 41,011） |
| 引擎 physical footprint 峰值 | **43.4G** | **41.9G** |
| 启动 | 109.0 s | 107.1 s |

- footprint 用 `vmmap` 每 15 s 采样一次。
- 读入速度随长度下降：30,000 token 时约 277 token/s，128,000 token 时 203-204 token/s。
- 写回答在 128K 之后是 24.5-25.3 token/s，短对话是 26.7-29.2 token/s。
- 容量从 32K 增加到 128K，按引擎报告的剩余 GPU 内存算，引擎多用了约 2.6 GiB（两个模型都是：39,453 → 36,776 和
  41,011 → 38,334 MiB）。

## 三种能耗模式对比

| | 低电量 | 自动 | 高电量 |
| --- | ---: | ---: | ---: |
| IQ2_XS 读入 128,000 token | 907.0 s，141.1 token/s | **631.8 s，202.6 token/s** | 660.8 s，193.7 token/s |
| Q2_0 读入 128,000 token | 897.6 s，142.6 token/s | **626.1 s，204.4 token/s** | 638.4 s，200.5 token/s |
| IQ2_XS 读完后写回答 | 24.5 token/s | 25.3 token/s | 24.3 token/s |
| Q2_0 读完后写回答 | 23.1 token/s | 24.5 token/s | 24.7 token/s |
| 追问首个 token（IQ2_XS / Q2_0） | 0.95 / 0.91 s | 0.94 / 0.88 s | 1.00 / 0.88 s |
| footprint 峰值（IQ2_XS / Q2_0） | 未保存 / 41.9G | 43.4G / 41.9G | 43.5G / 41.9G |

- **低电量 → 自动**：读入快 43.4-43.6%。
- **自动 → 高电量**：没有更快。读入慢了 4.4%（IQ2_XS）和 1.9%（Q2_0）。
  - Q2_0 那次每 30 s 采样后台负载：Chrome、WindowServer 和 Spotlight（`mds`）在跑，单个进程最高约 100% CPU（Chrome）。
  - IQ2_XS 那次和自动模式那两次都没有采样后台负载，所以这几个百分点不能归因于能耗模式。
  - `pmset -g therm` 两次都没有记录温度或性能警告。
- 剩余 GPU 内存三次完全一样。
- 自动和高电量的四次用的是同一份提示，回答逐字相同，都是 3/3。
- 低电量那两次的回答差一对引号（`项目代号为银杏`，自动和高电量是 `项目代号为“银杏”`），但也是 3/3。这不是能耗模式
  造成的。那时脚本读的是工作区里的文档，而 IQ2_XS（01:14）和 Q2_0（07:35）两次运行之后，提交 `dc047b5` 改了
  README 和 docs，提示随之变了。现在语料固定在 `dc047b5`。
- 读完后写回答只生成了 27 个 token，样本很小。

`../2026-10-03-metal-100k/` 那次 100K 运行，回答反复输出 "RAM"，没有找到埋入的字段。那时的引擎有 Q3_K 解量化
错误（PROGRESS 第 19 轮修复）。修复后的引擎在 128K 上找回了全部三个字段。不过这只是每个模型一个提示，不能证明
长文本的普遍质量。

## 复现

先确认接了电源，并且能耗模式不是低电量（`pmset -g | grep powermode`：0 自动，1 低电量，2 高电量），也关掉占
CPU 的应用。

```sh
.venv/bin/python bench/results/2026-10-04-metal-128k/long_context.py --config strata-iq2_xs.json
.venv/bin/python bench/results/2026-10-04-metal-128k/long_context.py --config strata-q2_0.json
```

一次只跑一个引擎。每次约 12 分钟。
